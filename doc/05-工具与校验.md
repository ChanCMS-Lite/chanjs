# 05 · 工具与校验：logger / Paths / 文件安全 / validate / utils 工具集

日常开发最常用的小工具。导出方式分两类：
- **根包直接导出**：`logger`、`Paths`、`validate`、`validateAll`。
- **`utils` 命名空间导出**：`import { getIp, request, tree, ... } from "chanjs/utils/index.js"`，
  或集中用 `import { utils } from "chanjs"` 后 `utils.getIp(...)`。

---

## 一、日志 `logger`

文件：`utils/logger.js`。基于 pino 单实例（`logger` 即 `root`），**dev/prd 均走 pino-pretty 人读输出**，
`base:null` + `ignore` 去掉 `pid/hostname/module/level` 固定头，时间只留 `HH:mm:ss`。例：
`[14:09:33]: GET /cms/field/findByMid?mid=11 200 3ms`

### 1.1 默认实例 `logger`

```js
import { logger } from "chanjs";   // logger 是具名导出（默认导出是 Chan 主类）

logger.info("服务启动");
logger.warn("缓存未命中");
logger.error("数据库连接失败", err);   // 第二个参数传 Error 会自动解析堆栈
logger.debug("调试信息", { userId: 1 });
```

| 方法 | 级别 | 说明 |
|---|---|---|
| `trace` | 0 | 最细 |
| `debug` | 1 | 调试（dev 默认开启）|
| `info` | 2 | 常规信息（prd 默认开启）|
| `warn` | 3 | 警告 |
| `error` | 4 | 错误 |
| `fatal` | 5 | 致命 |

**级别控制**：唯一环境变量 `LOG_LEVEL`（默认 `info`），低于该级别的日志不输出——不读 `NODE_ENV`，级别只看这一个变量。
**输出目标**：pino + pino-pretty，统一 stdout。本地开发直接看控制台；线上由 pm2 捕获 stdout 落盘（框架不写日志文件、不接自定义管道）。格式固定为「时间戳 + 正文」，`pid/hostname/module/level` 固定头已忽略。

### 1.2 子日志 / 链路日志

需要区分来源或携带上下文时，用 pino 原生 `child`（不要再造 logger 实例）：

```js
import { logger } from "chanjs";

const reqLog = logger.child({ userId: 1 });   // 绑定字段，每行自动附带
reqLog.info("用户登录");
// [14:09:33]: 用户登录 {"userId":1}
```

请求链路：`middleware/log.js` 已为每个请求注入 `req.log`（`logger.child({ requestId })`）与 `req.id`，Controller 内直接用。

### 1.3 传 Error 自动解析

```js
try { /* ... */ }
catch (err) {
  logger.error("操作失败", err);   // 自动输出 message + 堆栈文件:行号
}
```

## 二、路径 `Paths`

```js
import { Paths } from "chanjs";

Paths.rootPath;     // 项目根目录（process.cwd()）
Paths.appPath;      // app
Paths.configPath;   // config
Paths.publicPath;   // public
Paths.modulesPath;  // app/modules
Paths.commonPath;   // app/common
Paths.helperPath;   // app/helper
Paths.extendPath;   // app/extend
```

> 框架在 `Chan` 构造时已注入 `this.paths = Paths`，业务里通过 `this.app.paths` 访问，避免到处拼相对路径。
> 各路径均为 getter 动态计算（基于 `rootPath`），改 `rootPath` 会同步生效。

## 三、文件安全 `safePath`（防路径穿越）

文件：`utils/file.js`。**仅通过子模块深导入使用**：`import { safePath } from "chanjs/utils/file.js"`。
（它未挂在 `utils` 命名空间里，需直接指向子模块文件。）

```js
import { safePath } from "chanjs/utils/file.js";

const safe = safePath(userInputPath);   // 防御目录穿越(../)，合法返回绝对路径，非法返回 null
```

| 方法 | 说明 |
|---|---|
| `safePath(input)` | 以项目根目录为基准规范化路径，阻断 `../` 穿越；合法返回绝对路径，非法（越界/绝对路径）返回 `null` |

> 文件上传/在线编辑（如 ChanCMS 的 `vip` 模块）任何由用户输入拼出来的文件路径，都必须过 `safePath`，
> 否则用户可读取 `/etc/passwd` 等任意文件。**复用框架提供的安全函数，不要自己拼路径。**

## 四、参数校验 `validate` / `validateAll`（基于 zod）

文件：`middleware/validate.js`。用 **zod** 做声明式校验，校验通过的参数统一挂到 `req.validated`。
（校验失败自动抛 `ValidationError`，由全局错误处理器返回，你**不用手写 if 判断**。）

### 4.1 `validate(schema, source="body")` —— 校验单一来源

```js
import { validate } from "chanjs";
import { z } from "zod";

const createRule = z.object({
  title: z.string().min(1, "标题必填"),
  content: z.string().min(5, "内容至少5字"),
  status: z.number().int().optional(),
});

router.post("/article/create", validate(createRule), ctrl.create.bind(ctrl));
```

在 Controller 里取校验后的值：

```js
async create(req, res) {
  const data = req.validated;   // 已通过校验、且被类型转换过的数据
}
```

| 参数 | 类型 | 说明 |
|---|---|---|
| `schema` | zod schema | 校验规则 |
| `source` | `"body"\|"query"\|"params"` | 校验来源，默认 `body` |

> ⚠️ Express 5 的 `req.query` 是只读 getter，框架内部用 `defineProperty` 处理过，
> 统一用 `req.validated` 最稳（不要用 `req.query` 读校验后的值）。

### 4.2 `validateAll(schemas)` —— 多来源一起校验

```js
const listRule = {
  query: z.object({ current: z.coerce.number().int().min(1).default(1),
                    pageSize: z.coerce.number().int().max(100).default(10) }),
  params: z.object({ cateId: z.coerce.number() }),
};

router.get("/cate/:cateId", validateAll(listRule), ctrl.list.bind(ctrl));

// Controller 里：
async list(req, res) {
  const { query, params } = req.validated;   // { query:{current,pageSize}, params:{cateId} }
}
```

> `validateAll` 会把 `body/query/params` 各自校验后聚合成 `req.validated = { body, query, params }`，
> **不会用单一来源覆盖其他来源**（旧版有此 bug，已修复）。

### 4.3 常用 zod 写法速查

```js
import { z } from "zod";

z.string().min(1)                // 非空字符串
z.string().email()               // 邮箱
z.number().int().positive()      // 正整数
z.coerce.number()                // 把字符串"5"转成数字 5（表单常用）
z.boolean().optional()           // 可选布尔
z.array(z.string())              // 字符串数组
z.object({ a: z.string() })      // 嵌套对象
z.enum(["on","off"])             // 枚举
```

## 五、`utils` 工具集（全部方法）

以下全部可从 `chanjs/utils/index.js` 具名导入，或经 `import { utils } from "chanjs"` 后通过 `utils.xxx` 调用（除 `safePath` 见第三节）。

### 5.1 IP 与网络

| 函数 | 签名 | 返回 | 说明 |
|---|---|---|---|
| `getIp` | `getIp(req)` | string | 取客户端真实 IP（Express 专用）。优先 `cf-connecting-ip`（需 `CF_ENABLED=true` 且带 `cf-ray`），其次 `req.ip`（已融合代理链），兜底 `0.0.0.0`。自动处理 IPv6 映射/IPv6 回环 |
| `request` | `request(url, options?)` | Promise<{success,data,error?}> | 带超时/重试/SSRF 防护/大小限制的 HTTP 请求封装。`options`: `timeout`(默认 10000)、`retry`(默认 0)、`parseJson`(默认 true)、`responseType:"arraybuffer"`、`maxResponseBytes`(默认 10MB)。拦截私网/回环地址（防 SSRF）|

```js
import { utils } from "chanjs";

const ip = utils.getIp(req);
const { success, data, error } = await utils.request("https://api.example.com/x", { timeout: 8000, retry: 2 });
```

### 5.2 时间格式化

| 函数 | 签名 | 返回 | 说明 |
|---|---|---|---|
| `formatTime` | `formatTime(timestamp, format="YYYY-MM-DD HH:mm:ss")` | string | 时间戳/日期串/Date 格式化为字符串。非法时间原样返回 |
| `formatDateFields` | `formatDateFields(data, fields)` | 原类型 | 批量格式化对象/数组里指定日期字段（`fields` 数组）。非日期字段值不改动 |

```js
import { formatTime, formatDateFields } from "chanjs/utils/index.js";

formatTime(Date.now());                       // "2026-08-13 17:30:00"
formatDateFields(row, ["created_at","updated_at"]);
```

### 5.3 树形结构

| 函数 | 签名 | 返回 | 说明 |
|---|---|---|---|
| `tree` | `tree(list, rootPid=0, {maxDepth=20,idKey="id",pidKey="pid"})` | Array | 扁平数组转树（预建 Map 优化）；节点自带 `children`/`level`，无孩子则删 `children`。含循环引用/深度保护 |
| `treeById` | `treeById(targetId, list, {maxDepth=20,idKey="id",pidKey="pid"})` | Array | 按节点 ID 向上追溯完整父级路径 `[根...父...目标]` |

```js
const treeData = tree(categoryList, 0, { idKey: "id", pidKey: "pid" });
const path = treeById(25, categoryList);   // [根分类, ..., 目标分类]
```

### 5.4 数据解析

| 函数 | 签名 | 返回 | 说明 |
|---|---|---|---|
| `arrToObj` | `arrToObj(arr, keyField="config_key", valueField="config_value")` | object | 对象数组转键值映射（如配置列表）。入参非数组返回 `{}` |
| `getChildrenId` | `getChildrenId(py, source)` | `{ cate, id }` | 按拼音/ID 在分类数组中匹配，返回 `{ cate, id }`（找不到 `id` 为 `""`）|
| `filterFields` | `filterFields(data, fields)` | Array | 从对象数组筛选指定字段，返回全新数组（不改动原数据）。`data` 非数组返回 `[]` |

```js
const map = arrToObj(configList);                 // { site_name: "xxx", ... }
const picked = filterFields(rows, ["id","title"]); // 只保留两列
```

### 5.5 HTML 处理

| 函数 | 签名 | 返回 | 说明 |
|---|---|---|---|
| `htmlEncode` | `htmlEncode(str)` | string | 标准 HTML 实体编码（`& < > " '`），适配 art-template `{{ }}` |
| `htmlDecode` | `htmlDecode(str)` | string | HTML 实体解码（命名/十进制/十六进制）|
| `escapeScript` | `escapeScript(str)` | string | 危险标签（script/iframe/object/embed/form）二次转义，适配 art-template `{{@ }}` 防 XSS |
| `filterImgFromStr` | `filterImgFromStr(str)` | string[] | 从 HTML 源码批量提取全部 `img` 的 `src` 列表 |

```js
import { htmlEncode, escapeScript, filterImgFromStr } from "chanjs/utils/index.js";

const safe = htmlEncode(userInput);
const imgs = filterImgFromStr(articleHtml);   // ["/uploads/a.jpg", ...]
```

### 5.6 文件操作（`chanjs/utils/file.js`）

除 `safePath`（第三节）外，文件工具均通过子模块导入：

| 函数 | 签名 | 返回 | 说明 |
|---|---|---|---|
| `delImg` | `delImg(filePath)` | boolean | 删除相对根目录的文件（经 `safePath` 防穿越）；不存在返回 `false` |
| `readFileContent` | `readFileContent(filePath)` | string | 读文本文件内容（utf8）；非法路径/不存在/非文件抛异常 |
| `saveFileContent` | `saveFileContent(filePath, content)` | void | 写/覆写文件，目录自动递归创建；非法路径抛异常 |
| `getFolders` | `getFolders(folderPath)` | string[] | 取目录下一级文件夹名（过滤隐藏目录）|
| `getHtmlFilesSync` | `getHtmlFilesSync(folderPath)` | string[] | 同步取目录下一级全部 `.html` 文件名 |

```js
import { delImg, readFileContent, saveFileContent, getFolders, getHtmlFilesSync } from "chanjs/utils/file.js";

const htmls = getHtmlFilesSync("public/themes/default");
saveFileContent("public/x.txt", "hello");   // 自动建目录
```

### 5.7 分页 HTML `pages`

| 函数 | 签名 | 返回 | 说明 |
|---|---|---|---|
| `pages` | `pages(current, total, pageSize, href, query="")` | string | 生成 Tailwind 风格分页 `<li>` 片段（不含外层 `<ul>`）。`totalPage<=1` 返回空串 |

```js
import { pages } from "chanjs/utils/index.js";

const html = `<ul>${pages(page, total, 10, "/news/", "")}</ul>`;
// 链接形如 /news/1.html /news/2.html ...
```

## 七、常见坑

1. **`logger` 是具名导出**：`import { logger } from "chanjs"`（花括号）；`chanjs` 的默认导出是 `Chan` 主类，别混。
2. **忘了 `await store` 但 `cache` 同步**：`store` 异步要 `await`，`cache` 同步不要 `await`。
3. **校验后读 `req.body` 而非 `req.validated`**：Express 5 下 `req.query` 只读，框架已用 `req.validated` 统一承载，优先用它。
4. **zod 数字不 coerce**：表单传来的是字符串，`z.number()` 会失败，记得 `z.coerce.number()`。
5. **`safePath` 不是根导出也不是 utils 成员**：必须用 `import { safePath } from "chanjs/utils/file.js"` 深导入；任何由用户输入拼出来的文件路径都得过它。
6. **`utils` 里没有 `pathGuard`**：那是旧文档臆造的，本框架没有该中间件，路径安全请用 `safePath`。
