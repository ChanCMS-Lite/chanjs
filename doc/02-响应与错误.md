# 02 · 响应与错误：success / fail / AppError / CODE

统一的响应格式和错误体系，是接口"好对接"的关键。Chanjs 提供两层：

1. **响应信封**：`success()` / `fail()`（Controller 里直接 `this.success` / `this.fail`）。
2. **错误对象**：`AppError` 及其子类（如 `ValidationError`、`ForbiddenError`），配合全局错误处理器，把异常自动转成标准 JSON。

---

## 一、响应信封（所有 JSON 接口统一）

无论成功失败，前端拿到的结构都是：

```json
{ "success": true,  "code": 0,    "msg": "操作成功", "data": {} }
{ "success": false, "code": 1008, "msg": "验证码错误", "data": null }
```

| 字段 | 含义 |
|---|---|
| `success` | 布尔，是否成功 |
| `code` | 业务码（见下文 CODE 表）|
| `msg` | 给前端的提示文案 |
| `data` | 业务数据，失败时为 `null` |

### 1.1 `success(opts)` / `this.success(opts)`

纯函数（可直接 `import { success }` 或 Controller 内 `this.success`）。

```js
success();                          // {success:true, code:0, msg:"操作成功", data:{}}
success({ data: [1,2,3] });         // 带数据
success({ data: row, msg: "查询成功" });
```

| 参数 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `opts.data` | any | `{}` | 返回数据 |
| `opts.msg` | string | `"操作成功"` | 提示 |

### 1.2 `fail(opts)` / `this.fail(opts)`

```js
fail("用户名已存在");                 // 字符串当 msg，code 默认 1008
fail({ code: 1006, msg: "参数缺失" });
fail({ code: 1008, data: {...} });  // 也可附带 data
```

| 参数 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `opts`(string) | string | — | 当 `msg`，`code=1008` |
| `opts.msg` | string | — | 提示 |
| `opts.code` | number | `1008` | 业务码 |
| `opts.data` | any | `{}` | 附带数据 |

> 也可以脱离 Controller 直接用裸函数：`import { success, fail } from "chanjs"`。
> 但**在 Controller 里优先用 `this.success/this.fail`**，因为它们已经在正确的 `this` 上下文里。

### 1.3 其它响应辅助函数

| 函数 | 签名 | 说明 |
|---|---|---|
| `routeNotFound` | `routeNotFound(req)` | 生成 404 路由不存在响应体：`{success:false,code:1004,msg:"请求的资源不存在",data:{path,method}}` |
| `serializeError` | `serializeError(err, exposeDetail=false)` | 把错误序列化成统一响应对象。AppError 提取 `code/msg`+自定义字段；原生错误生产环境脱敏（仅 `exposeDetail=true` 时附带堆栈）|
| `buildErrorHtml` | `buildErrorHtml(status, errorMsg, code, req)` | 生成内置兜底错误 HTML 页（无模板依赖）。4 个参数：`status`(HTTP 码)、`errorMsg`(文案)、`code`(业务码或 `HTTP_xxx`)、`req` |
| `respondError` | `respondError(res, req, { httpStatus=500, code=500, msg, data=null })` | 按请求类型分流：API（XHR / Accept=json）返回 JSON，浏览器页（Accept=html）渲染 HTML 错误页 |

```js
import { routeNotFound, serializeError, buildErrorHtml, respondError } from "chanjs";

const body = routeNotFound(req);                 // 404 体
const obj = serializeError(err, false);          // 错误→响应对象
respondError(res, req, { httpStatus: 403, code: 1003, msg: "无权限" });
```

> ⚠️ 旧文档把 `buildErrorHtml(err)` / `respondError(res, err)` 写成单参数是**错误**的，实际签名见上表。

## 二、错误码 CODE 字典

`CODE`（数字→文案映射）与语义常量 `CODE_XXX` 都从 `chanjs` 导出，避免硬编码数字。

```js
import { CODE, CODE_OK, CODE_AUTH_FAILED, getCodeMsg } from "chanjs";

CODE[0];              // "操作成功"（按业务码取提示文案）
CODE_OK;              // 0
CODE_AUTH_FAILED;     // 1001
getCodeMsg(1001);     // "认证失败"
```

### 2.1 完整 CODE 表（`response/code.js` 权威）

| 业务码 | 常量 | 文案 | HTTP 状态（对应错误类）|
|---|---|---|---|
| `0` | `CODE_OK` | 操作成功 | 200 |
| `1001` | `CODE_AUTH_FAILED` | 认证失败 | 401 |
| `1002` | `CODE_TOKEN_EXPIRED` | 令牌已过期 | 401 |
| `1003` | `CODE_FORBIDDEN` | 权限不足 | 403 |
| `1004` | `CODE_NOT_FOUND` | 资源不存在 | 404 |
| `1005` | `CODE_CONFLICT` | 资源已存在 | 409 |
| `1006` | `CODE_PARAM_INVALID` | 参数无效 | 422 |
| `1007` | `CODE_PARAM_MISSING` | 参数缺失 | 400 |
| `1008` | `CODE_BUSINESS_FAIL` | 业务处理失败 | 400 |
| `1009` | `CODE_RATE_LIMIT` | 请求过于频繁 | 429 |
| `1010` | `CODE_DEVICE_ERROR` | 登录设备异常 | 403 |
| `1011` | `CODE_BLOCKED` | 访问已被限制 | 403 |
| `5001` | `CODE_SYSTEM_ERROR` | 系统内部错误 | 500 |
| `5002` | `CODE_SERVICE_BUSY` | 服务繁忙，请稍后再试 | 503 |
| `6001` | `CODE_DB_CONNECTION_ERROR` | 数据库连接失败 | 503 |
| `6002` | `CODE_DB_ACCESS_DENIED` | 数据库访问被拒绝 | 503 |
| `6003` | — | 存在关联数据，操作失败 | 409 |
| `6004` | — | 数据库字段错误 | 400 |
| `6005` | — | 数据重复，违反唯一性约束 | 409 |
| `6006` | — | 目标表不存在 | 500 |
| `6007` | `CODE_DB_OPERATION_TIMEOUT` | 数据库操作超时 | 503 |
| `6008` | — | 数据库语法错误，请检查查询语句 | 500 |
| `6009` | — | 数据库连接已关闭，请重试 | 500 |

> 注：`CODE` 数字是完整权威来源；语义常量只覆盖了常用码（1001–1011、5001、5002、6001、6002、6007）。
> 未提供常量的码可直接用数字（如 `6005`）。

`getCodeMsg(code, fallback="操作失败")`：按码取默认文案，查不到返回 `fallback`。

## 三、AppError 错误族（推荐用"抛错"代替 `this.fail`）

比起在 Controller 里 `return this.fail(...)`，更优雅的是**直接 throw 一个错误对象**，
框架的全局错误处理器会自动把它转成标准 JSON。这样业务逻辑（Service/Repository）里也能直接抛。

### 3.1 基类 `AppError`

```js
import { AppError } from "chanjs";

// 构造：code(业务码), msg(文案), httpStatus(HTTP状态), cause(底层错误)
throw new AppError(1008, "用户名已存在", 400);
```

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `code` | number | ✅ | 业务码 |
| `msg` | string | ✅ | 提示 |
| `httpStatus` | number | ❌ | HTTP 状态，默认 400 |
| `cause` | Error | ❌ | 底层原始错误（会被记录进日志）|

> 🛑 **顺序不能写反**：`new AppError("用户名已存在", 1008)` 是**错的**（会把 msg 当 code）。
> 正确是 `new AppError(1008, "用户名已存在")`。

### 3.2 预定义子类（最常用）

这些子类已把 `code` 和 `httpStatus` 绑定好，你只管传文案：

```js
import {
  AuthError, TokenExpiredError, ForbiddenError, NotFoundError,
  ConflictError, ValidationError, ParamMissingError, BusinessError,
  RateLimitError, BlockedError, SystemError, ServiceBusyError,
  DbConnectionError, DbAccessDeniedError, DbTimeoutError,
} from "chanjs";

throw new ValidationError("标题不能为空");          // code=1006, http=422
throw new ForbiddenError("无权限");                  // code=1003, http=403
throw new NotFoundError("文章不存在");               // code=1004, http=404
throw new BusinessError("库存不足");                 // code=1008, http=400
throw new AuthError("请先登录");                     // code=1001, http=401
throw new RateLimitError("请求过于频繁");            // code=1009, http=429
```

**带额外字段**：`ValidationError` 支持第二个参数传字段列表（用于前端高亮）；`RateLimitError` / `BlockedError` 可传 `retryAfter`：
```js
throw new ValidationError("参数校验失败", ["title", "content"]);
throw new RateLimitError("请求过于频繁", 30);   // retryAfter = 30s
```

**带底层错误**：把数据库异常包进去，便于排查：
```js
try { await repo.insert(data); }
catch (e) { throw new SystemError("写入失败", e); }
```

**两种构造写法**（所有子类通用）：
```js
new ValidationError("标题不能为空");                       // 字符串当 msg
new ValidationError({ msg: "标题不能为空", fields: [...] }); // 对象写法，可带 extraProps / cause
```

### 3.3 辅助函数

```js
import { isAppError, describeError, errorExtraProps, parseStack, wrapDbError } from "chanjs";

isAppError(err);        // 判断是不是业务错误（AppError 实例）
describeError(err);     // 递归生成可读错误链路（含 ECONNREFUSED/ENOTFOUND 等智能提示 + cause 链）
errorExtraProps(err);   // 提取错误附加属性字符串，用于日志
parseStack(err.stack);  // 解析出 { message, file, line }，定位报错文件
wrapDbError(err);       // 把数据库底层异常转成对应 AppError 子类
```

**`wrapDbError` 很实用**：在 Repository 里 catch 数据库错误后调用，会自动映射成友好错误：
```js
import { wrapDbError } from "chanjs";
try { /* knex 操作 */ }
catch (e) { throw wrapDbError(e); }
// ER_DUP_ENTRY / 23505      → ConflictError("数据已存在")
// ER_ACCESS_DENIED_ERROR    → DbAccessDeniedError("数据库访问被拒绝")
// ER_NO_SUCH_TABLE          → SystemError("数据表不存在")
// ER_BAD_FIELD_ERROR        → ParamMissingError("数据库字段错误")
// ER_ROW_IS_REFERENCED_2    → ConflictError("存在关联数据，操作失败")
// ECONNREFUSED/ENOTFOUND/…  → DbConnectionError("数据库连接失败")
// 其它                       → SystemError("数据操作异常")
```

> `describeError` 内置递归深度限制（10 层）防栈溢出，并会展开 `AggregateError`。

## 四、完整示例：用抛错写业务

```js
import { Controller } from "chanjs";
import { ValidationError, NotFoundError } from "chanjs";
import { ArticleService } from "../service/ArticleService.js";

export class ArticleController extends Controller {
  constructor() { super(); this.service = new ArticleService(); }

  async detail(req, res) {
    const { id } = req.query;
    if (!id) throw new ValidationError("缺少 id");

    const row = await this.service.getById(id);
    if (!row) throw new NotFoundError("文章不存在");  // 抛错即可，框架接管响应

    this.success({ data: row });
  }
}
```

不用写 `try/catch` 返回失败——抛出 `AppError` 子类后，全局错误处理器会输出：
```json
{ "success": false, "code": 1004, "msg": "文章不存在", "data": null }
```

## 五、常见坑

1. **`AppError` 参数顺序写反**：`new AppError("消息", 1008)` → 实际 `code` 变成字符串，前端判断全错。永远是 `(code, msg, httpStatus)`。
2. **在 Service 里 `return this.fail`**：Service 没有 `this.fail`，请用 `throw new XxxError(...)`。
3. **裸 `throw new Error("xx")`**：会被当成系统错误（500），建议业务错误都用 `AppError` 子类。
4. **`code` 硬编码**：优先用 `CODE.XXX` 常量，避免数字漂移。
5. **`buildErrorHtml` / `respondError` 参数个数**：实际分别是 4 参和 3 参（见 1.3），旧文档单参写法是错的。
