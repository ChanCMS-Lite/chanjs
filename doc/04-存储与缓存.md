# 04 · 存储与缓存：store / cache

文件：`storage/index.js`，对外导出两个单例：`store`（Redis/内存适配层）和 `cache`（纯内存缓存）。
它们的 API 形状与 Redis 客户端保持一致，让业务侧无需关心底层是 Redis 还是内存。

> ⚠️ **`store` 与 `cache` 的 ttl 单位都是「毫秒（ms）」**，两者一致（旧文档称 cache 用秒是**错误**的）。
> 例：`store.set(k, v, 5*60*1000)` 与 `cache.set(k, v, 5*60*1000)` 都是 5 分钟。

---

## 一、`store` —— 通用键值存储（令牌黑名单 / 限流计数 / 临时状态）

`store` 背后优先用 **Redis**（配置了 `REDIS_ENABLED` 时），否则降级为**进程内 Map**。
因此它适合：登录态黑名单、限流计数、验证码、分布式锁等"需要跨请求/跨进程共享"的数据。
所有方法失败时返回安全默认值（`null`/`false`/`0`），**不会抛异常上抛**。

### 1.1 方法签名

```js
import { store } from "chanjs";

await store.init({ REDIS_ENABLED, REDIS });   // 框架启动时已自动 init，业务一般不用手动调
await store.set(key, value, ttl);             // 写入
const v = await store.get(key);               // 读取（不存在/异常返回 null）
await store.del(key);                         // 删除（不存在返回 false）
const ok = await store.exists(key);           // 是否存在（bool）
const n = await store.incr(key);              // 原子自增（新 key 返回 1，异常返回 0）
const n2 = await store.incrAndExpire(key, ttl); // 原子自增并设 TTL（限流专用）
await store.expire(key, ttl);                 // 为已存在 key 设过期（key 不存在返回 false）
const info = store.getInfo();                 // 诊断信息（健康检查用）
await store.close();                          // 关闭并释放资源（优雅停机自动调）
```

| 方法 | 签名 | 返回 | 说明 |
|---|---|---|---|
| `init` | `init({REDIS_ENABLED, REDIS})` | Promise | 框架启动自动调用；业务无需手动 |
| `set` | `set(key, value, ttl=60000)` | Promise\<boolean\> | `ttl` 单位**毫秒**；`ttl<=0` 视 Redis 为永久 |
| `get` | `get(key)` | Promise\<any\> | 未命中/异常返回 `null`（JSON 自动反序列化）|
| `del` | `del(key)` | Promise\<boolean\> | 删除；不存在/异常返回 `false` |
| `exists` | `exists(key)` | Promise\<boolean\> | 是否存在 |
| `incr` | `incr(key)` | Promise\<number\> | 原子自增；首次返回 1，异常返回 0 |
| `incrAndExpire` | `incrAndExpire(key, ttlMs)` | Promise\<number\> | 原子自增并设过期（限流场景专用），返回计数 |
| `expire` | `expire(key, ttlMs)` | Promise\<boolean\> | 给已存在 key 设过期；不存在返回 `false` |
| `getInfo` | `getInfo()` | `{mode, memorySize, redisConnected, circuitOpen}` | 诊断：当前后端模式/内存条目数/Redis 状态/是否熔断 |
| `close` | `close()` | Promise | 关闭 Redis、清空内存；优雅停机自动调 |

> ⚠️ **没有 `ttl(key)` 方法**（旧文档列出的是错误的）。想看剩余有效期可用 `getInfo()` 做健康诊断，
> 或直接用 `expire()` 续期。

### 1.2 实战：邮箱验证码

```js
import { store } from "chanjs";

// 发送验证码
await store.set(`email:code:${email}`, code, 5 * 60 * 1000);  // 5 分钟有效（ms）

// 校验验证码
const saved = await store.get(`email:code:${email}`);
if (!saved || saved !== inputCode) throw new BusinessError("验证码错误");
await store.del(`email:code:${email}`);
```

### 1.3 实战：JWT 黑名单（框架内部已用）

`security/jwt.js` 的 `revokeToken` 就是 `store.set("jwt:revoked:"+token, 1, ttl)`。
你无需直接使用，理解其机制即可。

### 1.4 降级与容错

- Redis 未开启 → 自动用内存 Map（**单机有效，多实例不共享**）。
- Redis 连接失败 → 框架 `warn` 并降级内存，不阻断启动。
- **熔断保护**：Redis 运行时连续失败 5 次触发熔断，30s 冷却期内全部走内存；冷却后自动尝试恢复。
- 黑名单查询异常时：默认 fail-open（放行），可用 `JWT_REVOCATION_FAIL_CLOSE=true` 切 fail-close。

## 二、`cache` —— 进程内内存缓存（热点数据 / 配置 / 模板变量）

`cache` 是**纯进程内 LRU + 惰性 TTL 缓存**（默认容量 10w，惰性清理间隔 10s、单批最多 1000 条）。
适合放"读多写少、允许短暂不一致"的数据，如站点配置、导航树、模板变量。它**更快、零网络开销**，
但**重启即丢、不跨进程**。方法都是**同步**的。

### 2.1 方法签名

```js
import { cache } from "chanjs";

cache.set(key, value, ttl);   // ttl 单位毫秒；不传默认 5 分钟；ttl<=0 视为永久
const v = cache.get(key);     // 命中返回原值；未命中/过期返回 null
cache.has(key);               // 是否存在（命中同样刷新 LRU）
cache.del(key);               // 删除，返回是否删除成功
cache.clear();                // 清空全部（慎用）
cache.size();                 // 当前条目数
const n = cache.incr(key, ttlMs);          // 原子自增（新 key 用默认 60s TTL）
const n2 = cache.incrAndExpire(key, ttlMs); // 自增并刷新过期（限流专用）
cache.expire(key, ttlMs);    // 为已存在 key 刷新过期；不存在返回 false
```

| 方法 | 签名 | 返回 | 说明 |
|---|---|---|---|
| `set` | `set(key, value, ttl=300000)` | void | `ttl` 单位**毫秒**（默认 5 分钟）；`ttl<=0` 永久 |
| `get` | `get(key)` | any | 未命中/过期返回 `null` |
| `has` | `has(key)` | boolean | 是否存在（刷新 LRU）|
| `del` | `del(key)` | boolean | 删除成功返回 `true` |
| `clear` | `clear()` | void | 清空（一般只在测试或全量刷新时用）|
| `size` | `size()` | number | 当前缓存条目数 |
| `incr` | `incr(key, ttlMs=60000)` | number | 原子自增；新建 key 起始值 1 |
| `incrAndExpire` | `incrAndExpire(key, ttlMs)` | number | 自增并刷新过期（限流/计数）|
| `expire` | `expire(key, ttlMs)` | boolean | 给已存在 key 刷新过期；不存在返回 `false` |

> ⚠️ `cache` 是**同步**的，不要画蛇添足 `await`；`store` 是**异步**的，必须 `await`。
> `set` 的 `ttl` 同样是**毫秒**——和 `store` 单位一致（旧文档的"秒"是错误）。

### 2.2 实战：缓存站点配置 30 分钟

```js
import { cache } from "chanjs";

async function getSiteConfig() {
  const hit = cache.get("site:config");
  if (hit) return hit;

  const cfg = await siteRepo.find({ type: "site" });
  cache.set("site:config", cfg, 30 * 60 * 1000);  // 缓存 30 分钟（ms）
  return cfg;
}
```

> ChanCMS 的 `web/middleware/init.js` 正是用 `cache` 把 `site/nav/category` 等全局变量缓存，
> 避免每次请求都查库。

## 三、store vs cache 怎么选

| 维度 | `store` | `cache` |
|---|---|---|
| 后端 | Redis（可降级内存）| 纯内存 LRU |
| 同步性 | 异步（返回 Promise，必须 `await`）| 同步（直接返回值）|
| 跨进程/多实例 | ✅（Redis 时）| ❌ 仅本进程 |
| ttl 单位 | 毫秒 | 毫秒（一致）|
| 典型用途 | 验证码、令牌黑名单、限流、分布式锁 | 配置、导航树、模板变量、热点列表 |
| 一致性要求 | 强（如注销要立即生效）| 弱（允许分钟级过期）|

**经验法则**：涉及"安全/状态正确性"用 `store`；涉及"性能/少查库"用 `cache`。

---

## 四、常见坑

1. **ttl 单位**：`store.set` 与 `cache.set` 的 ttl **都是毫秒**。写错会让缓存瞬间失效或永不过期。
2. **`store` 是异步**：方法返回 Promise 必须 `await`；`cache` 是同步的，别画蛇添足 `await`。
3. **`store.get` 返回 `null` 当"未命中"**：判断存在要用 `exists()`，不要 `if(get)` 区分（值为 `0`/`false` 也会误判）。
4. **`store` 没有 `ttl(key)`**：旧文档列出的该方法不存在，请用 `getInfo()` / `expire()`。
5. **内存 `cache` 重启即丢**：不要往 `cache` 放必须持久的数据（如未提交的订单）。
6. **Redis 未开时 `store` 仅单机**：多实例部署务必开启 `REDIS_ENABLED`，否则限流/黑名单不共享。
