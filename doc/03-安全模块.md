# 03 · 安全模块：JWT / XSS 过滤 / 关键词校验 / 限流 / 加解密

做登录、表单提交、评论、上传时必看。所有函数都从 `"chanjs"` 导出。

---

## 一、JWT 登录态（setToken / getToken / verifyToken / revokeToken）

文件：`security/jwt.js`。基于 `jsonwebtoken`，用 HS256 签名。黑名单存在 `store`（见 04 文档）。

### 1.1 `setToken(data, secretKey, expire="7d")` —— 签发令牌

```js
import { setToken } from "chanjs";

const token = setToken(
  { userId: 1, role: "admin" },   // 载荷（不要放密码等敏感信息）
  process.env.JWT_SECRET,         // 签名密钥（必须配，否则返回 null）
  "7d"                            // 有效期：'7d' / '2h' / 3600(秒)
);
// token 是字符串；secret 缺失返回 null
```

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `data` | object | ✅ | 载荷（用户标识等）|
| `secretKey` | string | ✅ | 签名密钥，通常取 `process.env.JWT_SECRET` |
| `expire` | string | ❌ | 有效期（数字按秒，字符串如 `'7d'`/`'2h'`），默认 `"7d"` |

> 登录成功后用 `res.cookie("token", token, {...})` 下发给浏览器（见 ChanCMS 的 `Member.login` / `SysUser.login`）。
> 会员端用的是 `ut` cookie（httpOnly），后台用 `token` cookie。

### 1.2 `verifyToken(token, secretKey)` —— 校验（异步）

```js
import { verifyToken } from "chanjs";

const { valid, reason, payload } = await verifyToken(token, process.env.JWT_SECRET);
if (!valid) {
  // reason: "missing" | "expired" | "invalid" | "revoked"
  throw new AuthError("登录失效");
}
console.log(payload.userId);
```

返回对象：

| 字段 | 类型 | 说明 |
|---|---|---|
| `valid` | boolean | 是否合法 |
| `reason` | string | 失败原因：`"missing"`（无 token）/ `"expired"`（过期）/ `"invalid"`（签名无效/伪造）/ `"revoked"`（已注销）|
| `payload` | object | 合法时的载荷 |
| `error` | Error | 失败时的原始错误（仅验签阶段）|

> 🔒 流程：先验签（无效/过期直接拒）→ 再查黑名单（已注销则拒）。

### 1.3 `getToken(token, secretKey)` —— 取载荷（校验成功才返回）

```js
const payload = await getToken(token, process.env.JWT_SECRET);
// 合法 → payload；非法 → null
```

### 1.4 `revokeToken(token, ttl)` —— 注销（加入黑名单）

```js
import { revokeToken } from "chanjs";

// 改密码/登出时调用：把旧 token 写入黑名单，ttl = 旧 token 剩余毫秒数
const decoded = await getToken(oldToken, secret);
const ttl = decoded.exp * 1000 - Date.now();   // 剩余有效期(ms)
await revokeToken(oldToken, ttl);
```

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `token` | string | ✅ | 要注销的令牌 |
| `ttl` | number | ✅ | 黑名单存活毫秒数（一般传 token 剩余有效期）；`<=0` 视为无需注销，直接返回 `true` |

> ⚠️ `revokeToken` 当前已在 `chanjs/index.js` 中显式导出（`import { revokeToken } from "chanjs"` 可直接用）。
> 新增 import 前仍建议核对 `index.js` 导出列表，避免漏导出导致整模块加载失败。

### 1.5 黑名单存储

`revokeToken` / `verifyToken` 的黑名单存在 `store`（见 04 文档）。Redis 开启时跨进程生效；
未开启时降级为内存（单机有效）。可用环境变量 `JWT_REVOCATION_FAIL_CLOSE=true` 切换为
"存储异常即拦截"（fail-close，适合金融/权限敏感场景）。

## 二、XSS 过滤 `filterXSS(data)`

文件：`security/xss-filter.js`。基于 `xss` 库，对用户输入做净化，**递归支持对象/数组/字符串**。

```js
import { filterXSS } from "chanjs";

const clean = filterXSS(userHtml);          // 字符串：去掉 <script>、onerror= 等危险内容
const cleanObj = filterXSS({ title, body }); // 对象/数组：逐字段递归净化
```

| 参数 | 类型 | 说明 |
|---|---|---|
| `data` | string \| object \| Array | 待净化数据；字符串直接净化，对象/数组递归处理（循环引用安全）|
| **返回** | 同输入类型 | 净化后的数据；`number/boolean/null/undefined` 原值返回 |

**使用场景**：评论、留言、富文本字段入库前净化；或渲染前净化。
ChanCMS 在 `BookChapter` 保存章节内容时复用它（**复用优先，不要自己重写**）。

## 三、关键词 / 安全校验 `checkKeywords(text, options?)`

文件：`security/checker.js`。检查文本是否命中敏感词 / 攻击特征（SQL 注入、命令注入、XSS、路径穿越等）。

```js
import { checkKeywords } from "chanjs";

const hit = checkKeywords(commentText);
if (hit) {
  // hit = { category: "xss", keyword: "<script" }
  throw new BusinessError(`内容包含违规词：${hit.keyword}`);
}
```

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `text` | string | ✅ | 待检测文本（空白直接返回 `null`）|
| `options.scope` | `"body"` | ❌ | 传 `"body"` 时跳过「路径/文件/英文词」等易误杀的分类（wholeWord/extensions/directories/sensitiveIdentifiers/encoding），只对语义敏感词做匹配；不传则全量扫描 |

**返回**：命中时 `{ category: string, keyword: string }`；未命中或空白时 `null`。

> ⚠️ **返回结构不是 `{ blocked, reason, keyword }`**（旧文档有误）。命中对象含 `category`（分类，如 `sqlInjection`/`xss`/`commandInjection`）和 `keyword`（命中的具体词）。
> 判断"是否命中"用 `if (hit)` 即可。

**`scope:"body"` 为什么重要（真实踩坑）：**
评论、留言这类"正文"里常含正常链接（如 `https://example.com/a.html`），若按全量规则扫描会误判为攻击。
传 `scope: "body"` 可只匹配语义敏感词，放行正常链接。

```js
// 正文内容检测（推荐）
checkKeywords(content, { scope: "body" });

// URL / 路径检测（默认全量）
checkKeywords(someUrl);
```

### 3.1 路径忽略校验 `isIgnored(path, ignorePaths)`

配套工具：判断请求路径是否命中忽略列表（大小写不敏感、去尾斜杠，支持精确/前缀匹配）。
> 注意：`isIgnored` 未挂到包根导出，需用深导入：`import { isIgnored } from "chanjs/security/checker.js"`。

```js
import { isIgnored } from "chanjs/security/checker.js";

isIgnored("/api/health", ["/api/health", "/public"]); // true
```

| 参数 | 类型 | 说明 |
|---|---|---|
| `path` | string | 当前请求路径 |
| `ignorePaths` | string[] | 忽略路径列表 |
| **返回** | boolean | 命中返回 `true` |

## 四、接口限流 `createRateLimitMiddleware(opts)`

文件：`security/rate-limit.js`。防止爆破 / 刷接口。**按 IP + UID 双维度限流**（自动从 `req` 取客户端 IP 与 `req.user?.uid`）。

```js
import { createRateLimitMiddleware } from "chanjs";

const emailLimiter = createRateLimitMiddleware({
  windowMs: 5 * 60 * 1000,   // 时间窗口：5 分钟（支持数字毫秒 或 "1s"/"1m"/"1h"/"1d" 字符串）
  max: 10,                    // 窗口内最多 10 次（默认 60）
  ignorePaths: ["/api/health"], // 这些路径跳过限流（默认 []）
});

router.post("/sendEmail", emailLimiter, ctrl.sendEmail.bind(ctrl));
```

| 参数 | 类型 | 必填 | 默认 | 说明 |
|---|---|---|---|---|
| `windowMs` | number \| string | ❌ | `60000` | 时间窗口：数字按毫秒；字符串形如 `"1m"`（s/m/h/d 单位）|
| `max` | number | ❌ | `60` | 窗口内最大请求数（IP 维度和 UID 维度各自独立计数）|
| `ignorePaths` | string[] | ❌ | `[]` | 命中即跳过限流的路径前缀列表 |

> ⚠️ **旧文档的 `keyPrefix` / `limitKey` 选项不存在**——当前实现固定为「IP + 登录用户 UID」双维度，无法自定义维度函数。
> 超限时中间件直接返回 **`code=1009`（`CODE_RATE_LIMIT`，HTTP 429）**，无需你手写。
> 存储异常时 fail-close 直接拦截（同样返回 429）。

## 五、对称加解密 `aesEncrypt / aesDecrypt`（⚠️ 异步）

文件：`security/sign.js`。基于 AES-256-GCM（内置 scrypt 密钥派生 + LRU 缓存），用于加密敏感字段（如配置里的密钥）。

```js
import { aesEncrypt, aesDecrypt } from "chanjs";

// ⚠️ 这两个函数是异步的，必须 await！
const cipher = await aesEncrypt(plainText, secretKey);   // 输出 iv+tag+密文 合并 base64
const plain  = await aesDecrypt(cipher, secretKey);
```

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `data` | string \| object | ✅ | 明文（对象会被 JSON 字符串化）/ 密文 |
| `secretKey` | string | ✅ | 派生密钥的口令；建议统一配置环境变量 `AES_SALT` 固定盐值（未配置会有一次告警并用 secret 派生）|

> 🛑 **大坑**：`aesEncrypt` / `aesDecrypt` 是 **`async` 函数**，调用必须 `await`。
> 漏写 `await` 会得到 `Promise` 而非字符串，后续比较/存储会全部错位。

## 六、安全模块速查表

| 函数 | 同步/异步 | 典型用途 | 注意 |
|---|---|---|---|
| `setToken` | 同步 | 登录签发 | secret 缺失返回 null |
| `getToken` | 异步 | 取载荷 | 非法返回 null |
| `verifyToken` | 异步 | 校验 | 先验签再查黑名单；reason 含 `revoked` |
| `revokeToken` | 异步 | 登出/改密注销 | 需传剩余 ttl(ms) |
| `filterXSS` | 同步 | 富文本净化 | 支持对象/数组递归；复用，别重写 |
| `checkKeywords` | 同步 | 敏感词 | 命中返回 `{category,keyword}`，未命中 `null`；正文用 `scope:"body"` |
| `isIgnored` | 同步 | 路径跳过判断 | 配合限流/扫描忽略列表 |
| `createRateLimitMiddleware` | 同步(返中间件) | 限流 | 选项 `{windowMs,max,ignorePaths}`；超限 `code=1009` |
| `aesEncrypt` / `aesDecrypt` | **异步** | 字段加密 | 必须 `await` |

## 七、综合示例：登录 + 限流 + 注销

```js
import { Controller } from "chanjs";
import { setToken, getToken, revokeToken } from "chanjs";
import { createRateLimitMiddleware } from "chanjs";
import { AuthError } from "chanjs";

const loginLimiter = createRateLimitMiddleware({ windowMs: 10*60*1000, max: 5 });

export class UserController extends Controller {
  async login(req, res) {
    const { username, password } = req.body;
    const user = await this.service.verify(username, password);  // 业务校验
    if (!user) throw new AuthError("账号或密码错误");

    const token = setToken({ userId: user.id }, process.env.JWT_SECRET, "7d");
    res.cookie("token", token, { httpOnly: true, sameSite: "strict" });
    this.success({ data: { token, user } });
  }

  async logout(req, res) {
    const token = req.cookies.token;
    const payload = await getToken(token, process.env.JWT_SECRET);
    if (payload) {
      const ttl = payload.exp * 1000 - Date.now();
      await revokeToken(token, ttl);   // 加入黑名单
    }
    this.success({ msg: "已退出" });
  }
}
```
